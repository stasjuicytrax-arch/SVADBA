# Приём заявок с сайта

Сюда приходят заявки из попапа «Написать нам» и из формы в блоке 07.
Обработчик сохраняет заявку у себя и **после этого** шлёт уведомление в Телеграм.

## Что где лежит

| Файл | Зачем |
|---|---|
| `lead-handler.js` | вся логика: проверка полей, защита от спама, сохранение, уведомление |
| `server.js` | обычный Node-сервер (VPS, Timeweb, Beget с Node, REG.RU) |
| `yandex-function.js` | точка входа для Yandex Cloud Functions |
| `.env.example` | список переменных окружения |
| `data/leads.jsonl` | сами заявки, по одной в строке (создаётся сам) |

## 1. Завести бота

1. В Телеграме открыть **@BotFather** → команда `/newbot`.
2. Придумать имя и логин бота (логин заканчивается на `bot`).
3. BotFather пришлёт **токен** вида `1234567890:AAH...` — это `TELEGRAM_BOT_TOKEN`.
4. Написать своему боту любое сообщение (иначе он не сможет вам ответить).
5. Открыть в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найти
   в ответе `"chat":{"id":123456789` — это `TELEGRAM_CHAT_ID`.
   Если уведомления нужны в группу — добавить бота в группу, написать там сообщение
   и взять `id` группы (он с минусом).

Токен — как пароль. Он живёт только в переменных окружения на сервере,
в коде сайта его нет и быть не должно.

## 2. Поднять обработчик

### Обычный Node-хостинг или VPS

```bash
cp server/.env.example server/.env   # заполнить токен и chat_id
node server/server.js                # слушает PORT, по умолчанию 8080
```

Дальше nginx проксирует `https://ваш-домен/api/lead` на `127.0.0.1:8080`,
а сам процесс держится через systemd или pm2 — как принято на вашем хостинге.

### Yandex Cloud Functions

Загрузить папку `server/`, точка входа `yandex-function.handler`, Node.js 18+,
переменные окружения — из `.env.example`, `LEADS_FILE=/tmp/leads.jsonl`.
В облаке `/tmp` не вечный, поэтому заявки стоит дополнительно писать в лог функции
или в Yandex Database.

## 3. Подключить к сайту

В `js/config.js` вписать адрес обработчика:

```js
window.SITE_FORM_ENDPOINT = 'https://help-wedding.ru/api/lead';
```

Пока строка пустая, форма не делает вид, что заявка ушла: она честно пишет,
что не подключена, и показывает телефон.

## 4. Проверить

```bash
curl -X POST http://127.0.0.1:8080/api/lead \
  -H "Content-Type: application/json" \
  -d '{"name":"Тест","phone":"+7 (900) 000-00-00","consent":true,"form":"Проверка"}'
```

Ответ `{"ok":true}`, строка появилась в `server/data/leads.jsonl`, сообщение пришло в Телеграм.

## Что важно по закону (docs/LEGAL.md §2.3)

- Сервер с обработчиком должен стоять **в России** (Timeweb, Beget, REG.RU, Яндекс Облако).
  Vercel, Netlify, Cloudflare и прочий зарубежный хостинг для первичного приёма
  персональных данных не подходит — это нарушение локализации (152-ФЗ, штраф 1–6 млн ₽).
- Уведомление в Телеграм — уже **трансграничная передача**. Она допустима только
  после сохранения заявки в России и должна быть указана в уведомлении в Роскомнадзор
  и в политике обработки персональных данных.
- Если не хотите трансграничной передачи — уберите `TELEGRAM_BOT_TOKEN` из окружения:
  обработчик просто сохранит заявку и ничего никуда не отправит. Как альтернативу
  можно настроить письмо на Яндекс Почту (см. LEGAL.md §2.3).
- Вместе с заявкой сохраняются дата, версия согласия, страница и IP — это то,
  чем подтверждается согласие на обработку.
